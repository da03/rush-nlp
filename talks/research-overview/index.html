At the time, public instruction datasets were mostly curated or synthetic. Real conversations were held by companies. This made it hard to study actual behavior, safety problems, and long-tail use cases. (~45s)

WildChat is substantially more multilingual than earlier conversation datasets. We detected 68 languages, and only 53 percent of turns are in English. Chinese and Russian are the next largest languages. (~45s)

WildVis

Million-scale chat logs need an interactive viewer

  • Filter by language, country, toxicity, or text
  • Search individual conversations
  • Explore conversations in embedding space
Deng et al., “WildVis,” EMNLP 2024 Demo · wildvisualizer.com
Reading raw JSON is not practical at this scale, so we built WildVis. It combines structured filters, text search, and an embedding view that lets users inspect clusters and individual conversations. (~50s)

Implicit Chain of Thought

2023–2024
The second project is implicit chain of thought. (~10s)
motivation

Explicit chain of thought serializes every step

12 × 3 = ?
6 + 30
36
Longer reasoning means more generated tokens and more inference time.
Chain of thought improves reasoning, but every intermediate step is generated autoregressively. For a long calculation, the trace can be much longer than the final answer. We asked whether a model could learn from the trace without generating it at test time. (~55s)

Deng et al., “Implicit Chain of Thought Reasoning via Knowledge Distillation,” 2023.
The main contribution of this work was the concept: model reasoning does not have to be written in human language. A transformer can instead use continuous hidden states across its layers and directly produce the answer. Our first paper gave one implementation and showed that this was possible. (~1m)
result

Implicit CoT solves 5×5 multiplication directly

GPT-2 Medium · no CoT
1.9%

Exact match; task-specific training on augmented multiplication data; batch size 1.
On five-by-five multiplication, a GPT-2 Medium model without CoT gets 1.9 percent. The implicit model reaches 96.4 percent while directly producing the answer. Explicit CoT reaches 100 percent but is over five times slower in this setup. (~1m)
follow-up

Reasoning can be internalized gradually

  1. Start with the full chain of thought
  2. Remove a small number of reasoning tokens
  3. Finetune and repeat
Deng, Choi, and Shieber, “From Explicit CoT to Implicit CoT,” 2024.
In follow-up work, we use a simpler gradual procedure. Start from a model that generates the full trace, remove a few tokens, finetune, and repeat. This lets the model absorb the trace step by step instead of asking it to internalize everything at once. (~55s)
limitation

Hidden reasoning is harder to inspect

benefit
fewer output tokens
cost
less interpretability

Implicit CoT is a speed–transparency trade-off, not a universal replacement for explicit reasoning.

The main limitation is interpretability. Explicit traces are imperfect explanations, but they are still useful for inspection and debugging. Implicit CoT is therefore a trade-off, not a universal replacement for visible reasoning. (~45s)

NeuralOS

2024–2026
The third project is NeuralOS. (~10s)
approach

Every screen pixel is generated by a neural network

No real kernel · no installed applications · no fixed UI tree

Rivard et al., “NeuralOS,” ICLR 2026.
NeuralOS simulates an operating system with a generative model. Every pixel is generated. There is no real kernel, no installed application, and no fixed UI structure underneath the image. (~50s)
formulation

Predict the next frame after each user action

Current screenplus recent history
+
User actionmouse, click, or key
→
Next screengenerated frame
Feed the generated frame back into the model and repeat.
The model receives recent frames and the current user action, then generates the next frame. That generated frame becomes the next input. This is interactive autoregressive generation rather than a prerecorded video. (~55s)
architecture

An RNN stores state; diffusion renders the screen

RNN
tracks long-term OS state
diffusion model
renders the next frame
The architecture has two main pieces. An RNN maintains the long-term state with constant memory, and a diffusion model renders each screen. We found this division easier to train than one model doing both jobs implicitly. (~55s)
data

Random exploration prevents action shortcuts

Agent datahover near close, then click
→
Wrong shortcut“hover means close”
→
Random datahover without clicking
2K
agent demonstrations
120K
random-exploration demonstrations
Agent demonstrations contain strong correlations. An agent usually clicks immediately after hovering over a close button, so the model may learn that hover itself closes the window. Random exploration adds counterexamples and teaches the actual effect of each action. (~1m)
synthetic demonstrations

Doom was learned without being installed

generated desktop
double-click launches Doom
escape returns to desktop
Training videos were fabricated by adding an icon and splicing in gameplay.
Doom was never installed in the environment. We created synthetic demonstrations by adding an icon to the desktop and splicing gameplay into videos. The model learned to launch, simulate, and exit Doom from those demonstrations. (~1m)
progress

Resolution increased fourfold in 18 months

2024 · 256×256
2025 · 512×384
2026 · 1024×768

neural-os.com

The first version in 2024 was 256 square and could not reliably overfit simple actions. The paper system reached 512 by 384. The current public demo is 1024 by 768, four times as many pixels as the paper system. (~50s)

→

A computer-use analogue of a driving simulator.

One practical use is training and evaluating computer-use agents without exposing real machines, accounts, or money. It plays the same role as a learned driving simulator for autonomous vehicles. (~45s)

Program-as-Weights

2025–2026
The fourth project is Program-as-Weights. (~10s)
motivation

Some useful functions are easy to describe but hard to code

“Is this email urgent?”

Rules and regular expressions are brittle; a full LLM call is often excessive.

We focus on fuzzy functions such as urgency classification. They are easy to describe in language, but brittle as rules. Calling a large hosted model works, but it is expensive and adds a network dependency to every invocation. (~50s)
approach

Compile once; run locally

Natural-language spec“is this email urgent?”
→
Compile oncelarge model in the cloud
→
Run locallysmall frozen interpreter
After compilation: no API key, no internet, and no repeated large-model call.
A large neural compiler reads the specification once and emits a small program represented by weights. The program then runs locally on a frozen small interpreter. The large model is not called again for each input. (~50s)
implementation

One interpreter can run many programs

compiler
4B
used once per program
local runtime
0.6B + 23MB
shared interpreter plus one adapter
Our standard compiler has four billion parameters. It emits a roughly 23-megabyte LoRA adapter. The same frozen 0.6B interpreter is shared across all programs, so each additional function adds only a small adapter. (~1m)
API

The result is called like a normal function

# Compile and load a local function. fn = paw.compile_and_load( "Classify if an email requires immediate attention" ) # This call runs locally. fn("Need your signature by EOD!") # → "immediate"
The API is intentionally small. A natural-language specification is compiled and loaded, and the returned object is called like an ordinary Python function. Inference happens locally after the model is downloaded. (~45s)

Prompting Qwen3 0.6B gets 9.8 percent exact match on FuzzyBench. Prompting a 32B model gets 68.7 percent. The same 0.6B model with compiled PAW programs reaches 73.8 percent, with about fifty times less model memory. (~1m)

Our website helper uses thirty compiled programs, with twenty-eight in the live serving graph. Different programs handle routing, retrieval, answering, and validation, all on the same frozen 0.6B interpreter. (~55s)
a direction I am interested in

AI systems that can be customized to particular users and use cases

General models are useful; many applications also need behavior tailored to their data, constraints, and deployment setting.

To close, a broad direction I am interested in is AI that can be customized to particular users and applications. I think this overlaps with the work here at Adaption. (~30s)
